### How I build them

Most of the effort goes into what happens when things go wrong. A
comment-to-DM flow takes twenty minutes to build. Making one that doesn't
reply to its own replies, doesn't get the account restricted for messaging
the same person twice, and doesn't send duplicates when Meta retries a
webhook takes a lot longer, and that's the part a client is really paying
for. So each README starts with the ways it could fail, not the happy path.

None of it touches real client data. The sample data is invented and uses the
reserved `.test` domain, so nothing can resolve or receive mail by accident.
There are no credentials, keys or exports anywhere.

And nothing scrapes behind a login. Instagram and Faire both forbid it,
whatever a tutorial says. These tools use documented APIs and public pages.
